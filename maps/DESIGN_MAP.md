## Mandatory Pre-Implementation Gate

No visual, UI, panel, tool, Matrix, Molecule/MTraX, asset, style, token, preset, JavaScript-generated CSS, or visual factory change may start until the relevant maps have been consulted:

- Use `maps/CODEMAP.md` to locate the owning module and avoid creating duplicate visual systems.
- Use `maps/API_MAP.md` when the visual change exposes, consumes, or changes runtime APIs, globals, tool capabilities, or panel APIs.
- Use this file to identify the owning token source, style generator, factory, asset class, or generated CSS exception.
- Use `maps/ARCHITECTURE_MAP.md` when the visual change crosses Atome/eVe ownership, layer contracts, lifecycle, rendering, command flow, or runtime mode boundaries.

Implementation may proceed only after the design owner, existing reusable tokens or factories, boundary status, and required map updates are known.

## Design Model

Atome/eVe does not use a classic static HTML plus authored CSS architecture for product UI. The maintained product UI is created at runtime through JavaScript:

- DOM nodes are created by JavaScript factories.
- Style objects are passed through factory APIs or applied directly to elements.
- Shared tokens are exposed as JavaScript constants and CSS custom properties.
- Some modules inject `<style>` tags from JavaScript strings or generated rule objects.
- Static CSS files exist, but they are framework, vendor, or build artifacts rather than the main eVe design source.
- DOM `data-*` attributes are not a design or model source of truth. Product renderers may use them only for short roles, view ids, renderer hints, and transient UI state; visual caches, media sources, media identifiers, group timelines, and serialized model data belong to structured JavaScript state, stores, or renderer caches.
- `AtomGraph` visual, semantic, and focus order fields are structural/navigation projection data, not design tokens or product style rules. Design code must not infer product styling ownership from these fields; renderer and design surfaces remain responsible for visual tokens and paint output.
- `AccessibilityGraph` and `AccessibilityBridgeProjection` are semantic/navigation contracts, not visual style contracts. Product design code may consume their labels, roles, orders, and actions for accessible presentation, but must not treat bridge nodes as DOM ownership, CSS selectors, ARIA source-of-truth, or per-Atome visual styling state.
- Workspace scene layers are structural/render-order metadata, not style tokens. The eVe layer ids `project`, `dashboard`, `panel`, `mainMenu`, and `flower` may drive canvas ordering, focus order, and accessibility grouping, but visual color, spacing, radius, typography, panel chrome, and menu geometry must still come from the owning token modules and BevyUI tree builders.
- Tool palette child lists are renderer behavior state, not design metadata; `data-tool-children` and `data-source-tool-children` must stay absent from product DOM output.
- Media mount errors are runtime diagnostics, not DOM design state; visual surfaces may reflect media readiness, but `data-media-api-error` must not persist in exported product DOM.
- Canvas surfaces are dense renderer outputs and must expose a short `data-role` in maintained DOM exports so active surfaces can be counted, pooled, and audited.

## Ownership Boundary

### Atome Open Design Surface

Path: `atome/`

Role: Product-neutral assets, generic Squirrel component builders, framework CSS artifacts, and bundled vendor CSS.

Allowed responsibilities:

- Generic icons, logos, and reusable assets under `atome/src/assets/`.
- Generic Squirrel component builders under `atome/src/squirrel/components/`.
- Product-neutral Squirrel table templates and table style variants in `atome/src/squirrel/components/table_visual_contract.js`.
- Canonical open system-control builders for Button, Slider, Input, and Console when the control contract is product-neutral.
- Framework-level CSS artifacts such as `atome/src/css/squirrel.css`.
- Vendored library CSS such as `atome/src/js/leaflet.min.css`.

Forbidden responsibilities:

- eVe product chrome, panels, private tool styling, Matrix styling, MTraX/Molecule product styling, or branding composition.

### eVe Closed Design Surface

Path: `eVe/`

Role: Closed product design system, UI tokens, panel chrome, tool visuals, Matrix visuals, runtime style injection, and product interaction visuals.

Allowed responsibilities:

- Product tokens and CSS variable injection.
- Panel, dialog, footer, menu, ribbon, flower, Matrix, tool, Molecule, and MTraX visual systems.
- Product-specific style strings generated by JavaScript.
- Closed design composition and product interaction styling.

Forbidden responsibilities:

- Generic Atome framework style rules that must be reusable outside eVe.

## Explicit Open / Closed Design Contract

Design ownership follows product specificity:

- Atome open design may contain only product-neutral Squirrel component structure, reusable framework visual assets, shell-level CSS, vendor CSS, and generated framework artifacts.
- eVe closed design owns product chrome, panels, menu, ribbon, flower, Matrix, Finder-facing product UI, private tool visuals, Molecule/MTraX visuals, branding, and product-specific Atome object rendering.
- Static CSS files are not the source of truth for eVe product design. eVe product visuals must be driven by JavaScript tokens, factories, structured style objects, and documented generated style exceptions.
- Generated or vendored CSS may be referenced as an exception only when this map records its ownership and purpose.

Cross-boundary design rules:

- Atome modules must not import or depend on eVe product tokens, panel chrome, product factories, branding, or closed style generators.
- eVe design modules may consume Atome product-neutral assets or Squirrel component contracts, but must not redefine generic framework styling as closed product-only behavior.
- Product object styling for Atome instances inside eVe remains closed design behavior unless a reusable rendering contract is explicitly promoted to Atome.
- Any promotion of eVe visual behavior into Atome requires a product-neutral API, reusable token contract, tests or visual verification, and updates to `maps/CODEMAP.md`, `maps/API_MAP.md`, and `maps/ARCHITECTURE_MAP.md`.

## Organic Voice Assistant

Primary sources: `eVe/voice/assistant/assistant_visual_contract.js`, `eVe/voice/assistant/assistant_scene.js`, and `atome/renderers/bevy-core/src/assets/shaders/procedural_sdf.wgsl`.

- The assistant is one full-workspace `procedural_sdf` quad on the workspace `panel` band, after project content and before `mainMenu`; uniforms keep its visible shell centered at `clamp(240px, 38vmin, 420px)`, so stretching and ejection cannot expose an internal quad edge. It never creates a visible DOM node, renderer, or second canvas.
- While the assistant exists, the compositor captures the full-resolution workspace and runs the same attributed Bevy 0.19 separable Gaussian kernel horizontally then vertically into two reusable targets. The optical defaults use a 16 logical-pixel blur radius, a continuous spherical refraction capped at 24 logical pixels, a 48% glass mix, a 20% rim-refraction start, and a 10% exterior aura. Blur/refraction radii are converted to physical pixels with the active DPR before reaching the GPU, so their perceived strength remains stable on standard and Retina surfaces. The SDF replaces the sharp presentation sample only inside the shell, limits the interior tint to 5%, and combines a near halo with a broad low-frequency asymmetric falloff. No full-workspace dim or contact shadow is projected, so the workspace remains unchanged outside the assistant and the aura stays continuous around its floating base. All three offscreen targets deactivate when no procedural SDF consumes them.
- Its local panel order is 400 (normalized workspace order 1500), immediately above the normalized Dashboard token range and below panel/menu surfaces while the Atome tool remains available. Idle shell wobble, core drift and breathing run continuously; PCM/vowel frames add bounded speech pulse and morphing.
- Size is `clamp(240px, 38vmin, 420px)`. The outer translucent shell uses a saturated cyan-left/rose-right gradient, a pearl Fresnel contour, a directional white highlight, and tinted internal diffusion while keeping its silhouette; it breathes over 3.2 seconds at ±1.5%, and real PCM RMS adds at most ±4%.
- The warm rose/peach inner core owns neutral/A/E/I/O/U deterministic shapes, with its own pearl edge and soft directional highlight for relief. Runtime interpolation uses 45 ms attack and 90 ms release. During the real `user_turn` microphone capture opened after TTS and its acoustic drain, the existing material maps RMS through `smoothstep(0.015, 0.42, listening_rms)`: a low-opacity cyan B vein stays masked within the lower core and a bounded C modulation deforms only the existing shell contour. The microphone is closed while the assistant speaks, so its own playback can never animate B+C. Silence makes both response terms exactly zero, and neither effect alters blur, refraction, color identity, or any state without capture. `voice.visual.material_submit` samples the exact RMS and phase submitted to the shared renderer without adding a component, scene, or canvas. Listening, processing, speaking, and error states remain material dynamics rather than extra UI surfaces.
- The assistant record carries a localized accessibility status label; an unavailable local model/runtime exposes the localized error state and never switches to browser speech synthesis.
- Appearance prewarms invisibly, then reveals the central glow over 0–140 ms, inflates the core over 70–330 ms, and brings the shell from 92% to 100% over 150–420 ms. A 180 ms settle is bounded to 1.5%; disappearance freezes each current reveal and contracts it over 320 ms. The shader never switches hue variants during these transitions, preventing color flicker while preserving the cyan/rose identity.
- Direct assistant contact is canvas-owned and GPU-rendered above Dashboard BevyUI. Pointer sequences that begin on the canonical main toolbox remain owned by that toolbox until release, so Atome can still toggle Dashboard or close the assistant on hold and every other tool remains usable; Dashboard cards and project content remain protected. A single browser-to-SDF vector conversion owns both organic contact and ejection, keeping deformation aligned with the physical finger. While the pointer remains down, the shell stays attached and deforms continuously without starting ejection. Releasing inside the shell cancels ejection, springs back and starts the localized acknowledgement; releasing outside after entering the shell starts one inertial ejection along the start-to-release vector. The shell keeps a bounded longitudinal pull, transverse volume compensation, delayed core and final-15% fade. There is no split, cut or burst visual. The ephemeral record follows the foreground WebGPU workspace and is removed from every previously occupied scene. Opening says the localized welcome and every user close starts the localized farewell with its animation. Visual disappearance returns the interaction to the closed state immediately after scene cleanup; the captured voice session may finish its farewell without blocking the next opening. The Atome hold bridge bootstraps the singleton on demand, so closed always opens and active always closes independently of module boot timing.
