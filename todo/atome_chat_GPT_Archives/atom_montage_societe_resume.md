# Atom — Montage de la société
## Résumé de structure, partenaires, financement et modèle économique

**Statut :** note de cadrage  
**Objet :** présenter simplement le montage envisagé autour d’Atom / eVe / Gravity

---

# 1. Objet de la société

La société **Atom** aurait pour mission de porter, développer et faire reconnaître l’écosystème **Atom / eVe / Gravity**.

Son rôle ne serait pas de vendre les données ni de constituer une base centralisée.

Elle porterait principalement :

- la conception technique ;
- le développement open source ;
- la coordination scientifique ;
- la gouvernance du standard Gravity ;
- la certification des implémentations conformes ;
- les partenariats avec la recherche, la santé et les institutions.

---

# 2. Forme juridique envisagée

La piste privilégiée est une **SAS**.

Pourquoi une SAS plutôt qu’une SASU :

- plusieurs associés peuvent détenir des parts ;
- chacun peut avoir un vrai rôle politique dans la société ;
- la répartition du pouvoir peut être définie précisément dans les statuts ;
- la société reste souple pour faire entrer plus tard des investisseurs ou partenaires ;
- un associé peut aussi exercer des fonctions opérationnelles et, selon les conditions juridiques applicables, être salarié.

Le montage envisagé serait donc :

```text
Fondateur principal
→ présidence / direction stratégique

Frère
→ associé
→ rôle important dans les décisions
→ fonctions opérationnelles
→ rémunération salariale possible lorsque la société le permet
```

Les statuts et un éventuel pacte d’associés devront encadrer :

- répartition des parts ;
- droits de vote ;
- décisions réservées ;
- droit de préemption ;
- agrément des nouveaux associés ;
- départ d’un associé ;
- rachat ou transmission des parts ;
- propriété intellectuelle ;
- confidentialité.

L’objectif est d’éviter qu’un associé puisse céder librement ses parts à un tiers sans contrôle des autres.

---

# 3. Séparation entre le projet scientifique et la société

Deux éléments doivent rester clairement séparés.

## Le concept

Le **problème à trois corps** — eVe / Atom / Gravity — doit être présenté comme un projet scientifique et technique autonome.

Il doit pouvoir être :

- audité ;
- étudié ;
- publié ;
- amélioré ;
- utilisé comme base de recherche.

## La société

La société Atom porte :

- l’organisation ;
- les équipes ;
- les financements ;
- la propriété de la marque ;
- la certification ;
- la gouvernance ;
- les relations avec les partenaires.

La société ne doit pas rendre opaque le cœur scientifique du projet.

---

# 4. Open source

Le cœur technique de Gravity doit rester **open source**.

C’est un élément important du projet car la confiance repose sur la possibilité de vérifier :

- le code ;
- les règles de risque ;
- les algorithmes ;
- les seuils ;
- les mécanismes de destruction ;
- les conditions de publication.

L’open source n’est donc pas seulement un choix de diffusion.

C’est une composante de la sécurité et de la crédibilité scientifique du projet.

---

# 5. Partenaires de départ

Le projet possède déjà un cadre de partenariat crédible.

## Université

L’université peut apporter :

- validation scientifique ;
- chercheurs ;
- méthodologie ;
- publications ;
- projets de recherche ;
- accès à des réseaux académiques.

## CHU

Le CHU peut apporter :

- expertise médicale ;
- cas d’usage concrets ;
- validation de l’intérêt clinique ;
- protocoles de recherche ;
- confrontation du système aux besoins réels de santé.

## LIMOS

Le LIMOS pourrait être un partenaire informatique et scientifique important pour :

- sécurité ;
- algorithmique ;
- statistiques ;
- optimisation ;
- systèmes distribués ;
- formalisation du Gravity Reactor.

L’objectif ne serait pas de lui sous-traiter le projet, mais de **co-construire et valider scientifiquement certaines briques**.

---

# 6. Écosystème à construire

Au-delà de l’université, du CHU et du LIMOS, le projet pourra intégrer progressivement :

- médecins ;
- chercheurs ;
- spécialistes en statistiques ;
- experts en cybersécurité ;
- spécialistes du RGPD et des données de santé ;
- nutritionnistes ;
- chercheurs en activité physique et sport ;
- laboratoires ;
- organismes publics ;
- associations de patients ;
- acteurs institutionnels.

Le but est de créer un projet transversal, et non simplement une entreprise informatique.

---

# 7. Financement du développement

Le projet doit chercher en priorité des financements permettant de construire la technologie sans dépendre immédiatement d’un modèle commercial classique.

Sources possibles :

- aides à l’innovation ;
- programmes de recherche ;
- aides nationales ;
- financements européens ;
- partenariats universitaires ;
- appels à projets santé ;
- programmes liés à la cybersécurité et à la souveraineté numérique ;
- projets collaboratifs avec CHU et laboratoires.

Des organismes comme **Bpifrance**, les programmes nationaux d’innovation, les dispositifs européens et les appels à projets de recherche pourront faire partie des cibles du dossier de financement.

Le financement recherché doit couvrir notamment :

- salaires des fondateurs ;
- chercheurs ;
- ingénieurs ;
- sécurité ;
- audits ;
- infrastructure ;
- validation scientifique ;
- démarches réglementaires ;
- démonstrateurs.

Le but est que les fondateurs puissent travailler à temps plein sur le projet sans être obligés de vendre rapidement une version commerciale incomplète.

---

# 8. Pourquoi ne pas baser le modèle sur la vente du logiciel

Gravity doit être open source.

Vendre simplement :

- le code ;
- l’installation ;
- la maintenance ;
- du développement spécifique ;

ne constitue probablement pas un modèle suffisamment durable.

L’automatisation et l’IA vont progressivement réduire fortement la valeur économique de nombreuses tâches d’intégration et de maintenance.

Le modèle économique doit donc reposer sur quelque chose de plus difficile à reproduire que du code.

---

# 9. Le modèle économique retenu : la certification Gravity

La piste privilégiée est de faire de **Gravity un standard de confiance**.

Le code reste ouvert.

En revanche, une organisation qui souhaite déclarer :

> « notre système respecte officiellement le standard Gravity »

devra pouvoir passer par un processus de certification.

La valeur économique vient alors de :

- la certification initiale ;
- les audits ;
- les tests de conformité ;
- les renouvellements ;
- les contrôles de versions ;
- la certification de nouvelles implémentations ;
- la validation de produits ou infrastructures utilisant Gravity.

---

# 10. Pourquoi la certification est plus pérenne

Une IA peut :

- réécrire un logiciel ;
- générer une intégration ;
- automatiser une maintenance.

Elle ne remplace pas automatiquement :

- un standard reconnu ;
- une gouvernance scientifique ;
- une procédure d’audit ;
- une marque de confiance ;
- une certification acceptée par des institutions ;
- une responsabilité de conformité.

La société doit donc chercher à devenir **l’autorité de référence du standard Gravity**, plutôt qu’un simple fournisseur de logiciel.

---

# 11. Source de rémunération

À court terme :

```text
subventions
+ financements de recherche
+ projets collaboratifs
```

permettent de financer :

- salaires ;
- recherche ;
- développement ;
- sécurité ;
- structuration du projet.

À moyen et long terme :

```text
certification
+ renouvellement
+ audit
+ validation de conformité
```

deviennent la source de revenus récurrente.

Le but n’est pas de faire payer l’accès au code.

Le but est de faire payer **la preuve qu’une implémentation respecte réellement le standard**.

---

# 12. Positionnement

Atom pourrait se positionner comme :

> **une société technologique et scientifique qui développe un standard open source de confiance pour l’exploitation statistique de données sensibles.**

Le cœur du projet est public et vérifiable.

La valeur de la société repose sur :

- le standard ;
- la gouvernance ;
- l’expertise ;
- la certification ;
- le réseau scientifique ;
- la reconnaissance institutionnelle.

# 14. Résumé

Le montage envisagé est donc :

1. créer une **SAS** permettant aux fondateurs d’avoir un véritable rôle dans la gouvernance ;
2. conserver **Gravity open source** ;
3. construire le projet avec l’université, le CHU et potentiellement le LIMOS ;
4. financer d’abord la R&D par des aides publiques, scientifiques et européennes ;
5. éviter de dépendre à long terme de la vente de code ou de maintenance ;
6. faire de Gravity un **standard reconnu** ;
7. construire un modèle économique durable autour de la **certification, de l’audit et de la conformité au standard**.

L’objectif final n’est donc pas de vendre une boîte noire propriétaire.

L’objectif est de créer **un standard de confiance ouvert**, dont la société Atom devient la structure de référence, de gouvernance et de certification.
